# Emojis

Mentions are powerful enough that you can build much more with them. An emoji picker is just a mention where the display text does not match the query. We'll use `:` as the indicator: the user types `:smile`, picks from a list, and the shortcode is
replaced with the emoji itself. If the mention events are new to you, start with
[Mentions](/rich-text-formatting/mentions) and the
[User and channel mentions](/guides/user-and-channel-mentions) guide; this page reuses the
same flow.

## A shortcode table

Map each shortcode to the glyph it inserts:

```tsx
const EMOJIS = [
  { shortcode: 'smile', char: '😄' },
  { shortcode: 'heart', char: '❤️' },
  { shortcode: 'fire', char: '🔥' },
  { shortcode: 'rocket', char: '🚀' },
];
```

## Wiring it up

Register `:` as the only indicator and filter the table with the text typed
after it. Because people habitually close the shortcode (`:smile:`), strip a
trailing colon before matching:

```tsx
<EnrichedTextInput
  mentionIndicators={[':']}
  onStartMention={() => setOpen(true)}
  onChangeMention={({ text }) => setQuery(text)}
  onEndMention={() => setOpen(false)}
  // ...
/>;

const q = query.replace(/:$/, '').toLowerCase();
const suggestions = EMOJIS.filter(e => e.shortcode.startsWith(q));
```

When the user picks, [`setMention`](/api-reference/enriched-text-input#setmention) inserts the glyph as the mention's display
text. The `data-shortcode` makes a handy attribute if you ever need to reconstruct it:

```tsx
const pick = (emoji) => {
  ref.current?.setMention(':', emoji.char, {
    'data-shortcode': emoji.shortcode,
  });
};
```

Since the emoji glyph is the whole mention, drop the usual highlight so it
reads as plain text:

```tsx
const htmlStyle = {
  mention: {
    ':': {
      color: '#232736',
      backgroundColor: 'transparent',
      textDecorationLine: 'none',
    },
  },
};
```

## Try it out

Type `:` followed by a name - `:fire`, `:heart` - then tap a suggestion. The shortcode is replaced with a single emoji that you can place anywhere in the text.

## Custom emoji images

On web, iOS, and Android, pass a catalog to render recognized shortcodes as compact inline images:

```tsx
<EnrichedTextInput
  customEmojis={[
    { shortcode: ':party:', uri: 'https://example.com/party.gif' },
  ]}
  onCustomEmojiError={({ shortcode, uri }) => {
    // Refresh your catalog if this image URL is no longer valid.
  }}
/>
```

An omitted catalog behaves like an empty catalog.

Type, paste, or restore `:party:` to display its image. You can also complete a
`:` mention with `setMention(':', ':party:')`. Names start with a lowercase ASCII
letter or digit and contain up to 64 lowercase letters, digits, underscores, or
hyphens. A shortcode next to a Unicode letter, combining mark, digit, or underscore
stays literal. Code spans, code blocks, and other mention labels stay literal too.
A shortcode must share one formatting run to become an image.

Each emoji is one editing item: selection offsets and text-change events use one
`\uFFFC` character for it. The text-length limit counts its full shortcode length.
HTML and clipboard exports contain the shortcode text with its surrounding
formatting, so you can store and restore content without retaining image URLs.
Emoji images are not pasted-image attachments.

Catalog updates preserve selection and undo history. Removing a catalog entry
restores its shortcode text. Failed images display their shortcode and call
`onCustomEmojiError` once per shortcode/URI pair during the editor lifetime.
On iOS and Android, errors are deduplicated by URI. Changing the URI retries loading.
The caller owns catalog fetching and retry policy.

The image box scales with the editor font, preserves the image's aspect ratio,
and supports animated images through the platform image loader. Its accessible label is the shortcode.

iOS defers recognition during marked-text composition and uses shortcode-based undo
snapshots so catalog changes cannot invalidate historical selection ranges. Undo
restores literal text without immediately recognizing it again. The next text edit
resumes recognition. Native apps must be rebuilt to include custom emoji support.

Android retains shortcode text beneath atomic replacement spans. Recognition and
catalog changes update only those spans, preserving native text undo history.
Recognition waits for composing spans to finish. Public offsets map each emoji to
one character; HTML, clipboard, and length limits use the retained shortcode.
